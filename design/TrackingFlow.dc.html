Tracking
EasyPost creates a Tracker with every label and pushes tracker.updated; we poll only what goes quiet. Every event lands once, in a canonical vocabulary, then drives one state machine.

Shipment state machine · canonical statuses
label_created
accepted
in_transit
out_for_delivery
delivered
voided (from label_created only, before acceptance)
exception
returned_to_sender
delivered_unconfirmed (no scan 15 d after est.)
Exception is a flag, not a dead end. Any state can enter exception (address issue, damaged, held at office) and return to in_transit on the next movement scan. Exceptions notify the seller, not the customer, until they resolve.
Out-of-order events. Carriers deliver history late. State is derived from the max occurred_at among known events, so a late "accepted" never regresses a delivered shipment.
Cost control. Trackers are billed per label by EasyPost, so we never create extra ones; webhooks carry nearly every update and polling is capped per account per hour.
