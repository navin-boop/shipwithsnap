Billing & payments
Pay as you go on Stripe. A card saved once; every purchase is an authorize-then-capture PaymentIntent, so the card is never charged for a label that didn't get bought.

Stripe objects we use

One per Snap account · cus_… stored on accounts.
SetupIntent → PaymentMethod
Card saved with usage: off_session via Stripe Elements; 3DS happens here, once, so later charges don't prompt.
PaymentIntent
capture_method: manual, off_session: true, confirm: true, our idempotency key. Authorized before the buy, captured after.
Refund · Webhooks
Refund on the original PI when EasyPost reports refunded. Webhooks: payment_intent.*, charge.refunded, charge.dispute.created.
Rules
Authorize, buy, capture. Authorization fails → 402 card_declined with the decline code and an update-card link; nothing bought. Buy fails → cancel the PaymentIntent; the hold drops off the card. Capture happens in the same unit of work that records the label.
One charge per batch. Authorize the batch total, capture only what was actually bought (partial capture). Receipts list every label in the charge.
Refunds follow the carrier. Void → EasyPost refund request → on refunded, Stripe refund to the original card. Until then the Billing screen shows "pending".
Adjustments are their own charge. Carrier re-weighs arrive days later: a separate PaymentIntent with an explanatory email. If it fails, retry on days 1, 3, 7; buying is blocked while any adjustment is unpaid.
Disputes lock the account for new purchases until resolved; evidence (label, tracking scans) is attached automatically.
